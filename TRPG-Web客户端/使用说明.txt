TRPG Web 客户端 —— 使用说明
======================================================================

【这是什么】
  这是 TRPG（跑团）玩家端的浏览器客户端。纯静态页面（HTML/CSS/原生 JS），
  不需要 npm、不需要构建，解压后双击 start.bat 即可使用。

【运行前提】
  1) Windows 10 / 11（自带 PowerShell）；
  2) 已安装 Python 3.12 或更高版本，并且 python 在 PATH 中。
     验证方法：打开「命令提示符」输入  python -V  应显示 Python 3.12+。
     若提示「不是内部或外部命令」，请先安装 Python 并勾选 Add python.exe to PATH。

【三步上手】
  第 1 步：把「TRPG-服务端.zip」和「TRPG-Web客户端.zip」解压到【同一个父目录】下，例如：
             D:\trpg\TRPG-服务端\
             D:\trpg\TRPG-Web客户端\
           （不放在同一目录也能用，只是需要手动指定服务端地址，见下文第 4 节）

  第 2 步：先启动服务端 —— 进「TRPG-服务端」目录双击 start.bat。
           服务端会自动挑选 9210-9230 之间的空闲端口，并把端口写进
           TRPG-服务端\run\server.json。

  第 3 步：再启动本客户端 —— 进「TRPG-Web客户端」目录双击 start.bat。
           它会：
             · 自动挑选 8080-8090 之间的空闲端口；
             · 自动读 ..\TRPG-服务端\run\server.json 找到服务端地址；
             · 自动打开浏览器，访问 http://127.0.0.1:<客户端端口>/index.html
           （首次运行会自动创建 run\ 目录，属正常现象）

  停止：在「TRPG-Web客户端」目录双击 stop.bat。

【为什么要经过本地端口反代（重要，别跳过）】
  浏览器的同源策略会拦截「跨源」的 fetch 与 WebSocket 请求。
  如果直接用浏览器打开 index.html 并连到另一个端口的服务端，
  /api 与 /ws 会被浏览器拦掉，页面看起来像「连不上」。
  因此 start.bat 启动的这个小服务器同时做了两件事：
    1) 把 client\ 目录当静态站点托管；
    2) 把 /api/*、/access/*、/ws 同源反向代理到真正的服务端。
  页面地址里的 ?server= 参数填的是【本客户端自己的地址】而不是服务端端口，
  这是有意为之，请不要改成服务端端口，否则又会变回跨源被拦。

【第 4 节：手动指定端口与服务端地址】
  用法：  start.bat [端口] [服务端地址]
    start.bat
        -> 自动挑 8080-8090 空闲端口，自动发现服务端
    start.bat 8080
        -> 用 8080 端口，自动发现服务端
    start.bat 8080 http://127.0.0.1:9210
        -> 用 8080 端口，服务端固定指向 http://127.0.0.1:9210
    stop.bat 8080
        -> 停止 8080 端口上的本客户端（默认读 run\client.port，一般不用带参数）

  退出码：0 成功（或已在运行）| 1 环境错误 | 2 端口冲突 | 3 启动超时

【端口被占用怎么办】
  本客户端不会静默换端口：
    · 自动模式下会从 8080 开始找到第一个空闲端口；
    · 显式指定端口且被【别的程序】占用时，会打印占用者 PID 并以退出码 2 结束；
    · 若该端口上已经是【本客户端】在运行，则幂等处理：只打印现有地址，不重复启动。
  处理办法：换一个端口，例如 start.bat 8085；或先 stop.bat 再启动。

【解压后目录结构】
  TRPG-Web客户端\
    start.bat              <- 双击启动
    stop.bat               <- 双击停止
    自检.bat               <- 双击自检（环境/文件/端口/服务端连通性）
    使用说明.txt           <- 本文件
    README.md  CHANGELOG.md  LICENSE  .gitattributes  .gitignore
    client\                <- 客户端本体（6 个文件，零构建）
      index.html  app.js  app.css  strings.json  tokens.json  README.md
    scripts\               <- start.bat/stop.bat 的真正实现
      start.ps1  stop.ps1  serve.py  selfcheck.ps1
    docs\PLAYER-WEB.md     <- 玩家端设计/契约文档
    run\                   <- 首次启动后自动生成（端口发现文件与日志），可安全删除

【常见问题】
  Q: 双击 start.bat 一闪而过？
  A: 多半是没装 Python 或没在 PATH 里。先双击 自检.bat 看具体原因。

  Q: 只想先打开客户端看看，还没启动服务端，能跑吗？
  A: 能。start.bat 会照常启动并打开页面（退出码 0），页面顶部会出现一条中文提示条
     「请先启动服务端，或在本页填写服务端地址」。
     此时 /api 与 /ws 会返回 502 并附带中文说明，属预期行为，不是崩溃。

  Q: 页面打开但提示连不上服务端 / 502？
  A: 服务端没启动，或没被自动发现。
     先确认「TRPG-服务端」已双击 start.bat；
     两包不在同一父目录时，请显式指定：start.bat 8080 http://127.0.0.1:9210

  Q: 浏览器没有自动打开？
  A: 不影响使用。按屏幕提示的「客户端地址」手动复制到浏览器即可。

  Q: 想让脚本不自动弹浏览器（自动化测试用）？
  A: 启动前设置环境变量 TRPG_NO_BROWSER=1。

  Q: 端口 8080-8090 全被占用？
  A: 先 stop.bat 清理本客户端；仍冲突则用 start.bat <端口> 指定区间外的端口。

【自检】
  双击 自检.bat，会逐项检查并给出结论行：
    自检结果：PASS   或   自检结果：FAIL
  检查项：Python 版本 / client\ 6 个文件是否齐全 / 端口区间是否空闲 /
          能否连上服务端（服务端未启动时该项记为 WARN，不算失败）。

【监听地址（可配置）】—— 交付口径（R32 / t13；D-02 裁决 A）
  客户端默认监听 127.0.0.1（仅本机可访问）—— 安全默认，不对外暴露。
  如需让同一局域网内的其他机器访问，必须【显式】开启：
      start.bat 8081 http://127.0.0.1:9211 0.0.0.0
      powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start.ps1 -Port 8081 -BindHost 0.0.0.0
      set TRPG_CLIENT_HOST=0.0.0.0     （serve.py 直接启动时）
  注意：客户端是无鉴权静态页面，默认 loopback 正是为了避免误暴露到局域网；
  启动信息会打印  bind: <监听地址>:<端口>  以及全部可用 URL；
  run\client.json 的 host / bind / urls 三个字段同样记录了实际绑定地址。

- **R10/R11 地点交互面板**：加入桌面后在「桌面」视图底部自动出现（纯 JS 注入 DOM，不改 index.html / app.css）。
  点房间里的柜子 / 抽屉 / 门等**热区**即出现「查看 / 搜索 / 撬锁」等动作；
  敏感动作（撬锁、取走）会显示「已上报待主持人」，**先由主持人拍板**，允许后才出结果，且页面**无需刷新**即更新。
- **事件流服务端裁剪**：非 KP 视图由服务端裁剪（响应含 filtered=true），暗骰与 KP-only 事件整条不返回。
- **镜像不变量（强制）**：本包 client\ 与 ..\TRPG-服务端\player-web\ 是同一份页面，
  app.js / app.css / tokens.json / strings.json / index.html（及 README.md）**必须逐字节一致**；改动需两处同步并复核 sha256。
- 小提示：改了前端后若浏览器仍显示旧界面，请**强制刷新**（Ctrl+F5）。
