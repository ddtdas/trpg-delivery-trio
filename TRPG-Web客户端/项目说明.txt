【二、三件套对应关系与各自边界】
三个包是同一个跑团系统的三个交付面，可各自单独使用，也可解压到同一父目录并列使用：
  TRPG-服务端             主持端（KP/DM）界面挂在 /app/，玩家端网页挂在 /player/
                          默认端口自适应 9210-9230；启动后写 run\server.json 供客户端发现
  TRPG-Web客户端          独立浏览器客户端（玩家端 PC 版），可指向本机或局域网内的服务端
                          默认端口自适应 8080-8090
  TRPG-微信小程序客户端     玩家端 mobile 端（用微信开发者工具导入；小程序没有 bat 启动概念）
三者的后端是同一套。并列布局（解压到同一父目录）时，本客户端会**自动发现**旁边的服务端：
  依次探测 ..\TRPG-服务端\run\server.json 与 ..\trpg-server\run\server.json（任一命中即可）。

【三、本包的正确入口】
  start.bat       启动（双击即用；自动挑 8080-8090 中的空闲端口，也可 start.bat 8080 指定）
                  也可同时指定服务端地址：start.bat 8080 http://127.0.0.1:9210
  stop.bat        停止（读取 run\client.port 定位端口，确认端口释放后才收尾）
  自检.bat        解压后自检：Python / 客户端文件 / 端口区间 / 服务端连通性 -> PASS 或 FAIL
  使用说明.txt    完整使用说明（端口、地址、目录速览、反代原理、常见问题）
  README.md       客户端自身的说明文档

【四、为什么客户端要经过本地端口反代（重要）】
浏览器的同源策略会拦截跨源的 fetch 与 WebSocket。start.bat 拉起的小服务器同时做两件事：
  ① 把 client\ 目录当静态站点托管；
  ② 把 /api/*、/access/*、/ws 同源反向代理到真正的服务端。
因此页面地址里的 ?server= 参数填的是【本客户端自己的地址】，**不是服务端端口** —— 这是有意为之，
改成服务端端口会重新变成跨源并被浏览器拦截。

【五、重要：docs\PLAYER-WEB.md 含「源仓库内部作业痕迹」】
该文档来自源仓库，其中有两类内容**不随本包发布**，请不要去找：
  · 【待回填：...】标记（T3 截图与自测证据等，指向 evidence\ 目录，该目录不随包发布）；
  · 对内部构建工装 packaging\build-delivery.mjs 的引用（该脚本不随包发布）。
另外文档中提到的 docs\CROSS-END-CONTRACT.md、lib\ws-client.js、clients\miniprogram\ 等路径，
属于【另外两个包】里的文件，是正常的跨端引用，同样不在本包内。
**请以顶层 README.md / 使用说明.txt / 自检.bat 为准**，不要按 docs\ 里的内部路径去找文件。

【六、run\ 是运行时目录，初次解压时不存在属正常】
run\ 目录**不在包内**，是首次启动时由 start.bat 自动创建的，其中：
  · run\client.port —— 当前端口；stop.bat 停止后会删除；
  · run\client.json —— 端口/进程发现文件；stop.bat 停止后会删除；
  · run\client.log  —— 运行日志，保留不删。
因此：**初次解压后看不到 run\client.json 是正常的**（那时客户端还没启动）。
若同级目录下确实有 TRPG-服务端、却找不到 run\server.json，最常见的原因是**服务端没有在运行**
（该文件只在服务端运行期间存在，服务端 stop.bat 会删除它），而不是两个包不在同一父目录 ——
请先双击 TRPG-服务端\start.bat。自检.bat 会替你区分这两种情形。

【七、运行环境】
Windows 10 / 11；Python 3.12 或更高（安装时请勾选 "Add Python to PATH"）。
本客户端**零第三方依赖**，不需要 pip 安装任何包（只使用 Python 标准库）。

【八、示例地址说明】
文档与提示中出现的 192.168.10.110:9210 是**局域网部署示例值**，不是凭据，
也不代表必须使用该地址 —— 请以你实际部署的服务端地址为准。
