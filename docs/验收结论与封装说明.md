## 4. 三件套启动步骤（封装后）

```text
1. 解压三份 zip 到同一父目录（zip 内顶层即各自项目根）：
     D:\trpg\TRPG-服务端\
     D:\trpg\TRPG-Web客户端\
     D:\trpg\TRPG-微信小程序客户端\
2. 校验：Get-FileHash <zip> -Algorithm SHA256 对比同目录 *.sha256（摘要见 §3）。
3. 服务端：进入 TRPG-服务端\ → 双击 自检.bat（期望 PASS）→ 双击 start.bat
   （自动选择 9210-9230 空闲端口）→ 访问 http://127.0.0.1:<端口>/api/health 期望 200。
4. Web 客户端：进入 TRPG-Web客户端\ → 双击 自检.bat → 双击 start.bat
   （自动发现同父目录服务端 run\server.json；自动打开页面）。
5. 小程序：微信开发者工具「导入项目」选 TRPG-微信小程序客户端\ 本身
   （appid=touristappid；勾选「不校验合法域名」，project.config.json 已预置 urlCheck:false）。
6. 主持端：webapp token 调 POST /access/host/table 开桌 → POST /access/host/turn 开回合；
   玩家两端（Web/小程序）填 服务器地址 + mobile token + 连接码 + ID + 昵称 即可加入。
```

> 三端 token 见 `TRPG-服务端\configs\access_config.yaml`（分发前按 §1 条件 1 更换）。
> ⚠️ **启动脚本注意**：`scripts/_serve.py` 自己会打开 `run/server.log`，**外部不要再对同一文件做 `>>` 重定向**（句柄冲突会导致 `PermissionError` 起不来）；并且**从 ssh 会话用 `Start-Process` 起的进程会随会话结束被杀**，需用脱离方式（如 WMI `Win32_Process.Create`）启动。

5. **R35 死光全流程 3 项 FAIL（18/21 PASS）**：
   - `R35-2` 一次性下载物 sha256 与模组索引不一致：`dl=12,930B/5b0c9e9c…` vs `index=39,439/fd6a0211…` ⇒「按模组 id 下载并校验 sha256」不成立。**索引的 sha256/size 与可下载产物的 sha256 是两个不同量**，需在契约层明确索引应发布哪个。
   - `R35-7` GM 一次性落位未产生地图（`apply` 返回 201 但 `applied_count=0`）。
   - `R35-13b` NPC 自动叙事候选在 GM 审批列表中 `visible_to_players=False`。

6. **小程序渲染层验收 = BLOCKED（前置条件缺失）。** 工具链位于**本机 `DESKTOP-K8L76TP`**（不在 110），且卡点是 **IDE 用户档从未初始化**（`cli islogin` 报 `ENOENT ... User Data\<hash>\Default\.cli`），**需人工先启动一次 IDE 建档，再做扫码登录**。逻辑层已用 Node mock 验到 36/36，**渲染层未验**。

8. **`.gitattributes` 政策缺口（潜在风险，非当前交付缺陷）。** `*.whl`（包内 34 个）与 `*.modpkg`（包内 1 个）**未声明 `binary`**。打包器为**逐字节搬运**，故**本包内容不会被损坏**；风险只在**交付之后**的搬运环节（git checkout/archive、文本模式复制、带 EOL 转换的解压工具）。建议补 `*.whl binary` 与 `*.modpkg binary`。
9. **I17 判据的 docstring 与实现作用域不一致。** docstring 写「CRLF anywhere a reader will open it」，实现只扫 `modules/` + `rulepacks/`。**本轮裁决：声明作用域 = modules/ + rulepacks/，零字节改动**（验收期不改被验收对象）；`app/` 下的 CRLF 按第 7 条登记为已知 P2 卫生项。

## 8. 本轮方法论产出（建议随交付保留）

本轮三人团队在高压下收敛出一套**可复算的判据规范**，其价值超过任何单条缺陷修复：

- **判定口径 6 条**：不看退出码单值 / marker 必须编码无关（ASCII）/ 负向判据必须配阳性对照 / 对照须先证非真空 / 文档正确性不能由产生它的实验背书 / 数值更正前先写「这个数计的是哪个集合」。
- **流程约束 P1–P10**：探针以自己身份命名 · 「我停手了」须在最后一次写入之后发出且附全量账目 · 验证动作排在冻结快照之后 · 复跑记录增量 · 消息不内联数值/哈希 · 共享状态须声明读写 · 工具版本留同 sha 归档副本 · 过期判断显式作废（含镜像面：对他人的预期也须刷新）· 把保护从「约定」下沉为「构造」· 实施纠正前先确认对方是否已改。
- **负向搜索判定表**：`stdout 空 + stderr 非空` ⇒ 判「**未测到**」而非「未命中」；判空禁用 `@($x).Count`（`$null` 计为 1）；阳性对照必须**同一调用、同一主机、同一类对象**。
- **集合界定错误 11 例（三人各有）**，方向含「样本小于全集 / 转写漏项 / 口径窄于全集 / 假匹配 / 来源混用」——**无一是判断力问题，全部是集合与口径层面**。
- **同类工具陷阱 3 例**：PS 5.1 的 inline-`if` 静默丢弃输出行 · 正则多转义导致假阴性 · 观测落在两处改动之间取到过期值。**共同形态：判据工具的语法或时点会静默给出错误结论。**
